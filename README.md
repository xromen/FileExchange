# Файловый обмен

Программа на C# для Windows 10 и Windows 11 x64. Добавляет в контекстное меню файлов и папок группу **«Файловый обмен»** с настраиваемыми папками назначения, включая новое меню Windows 11. Копирует выделенные файлы и папки рекурсивно, сохраняя исходники. При совпадении имени файла запрашивает разрешение на перезапись; в конце всегда показывает количество скопированных файлов, созданных папок, пропусков и ошибок.

Скачайте `FileExchange-<версия>-win-x64.zip` в разделе **Releases** своего GitHub-репозитория и распакуйте целиком. Установленная .NET для запуска не нужна.

Запустите **`FileExchange.Manager.exe`** — WPF-приложение запросит права администратора. Нажмите **«Установить / обновить»**, затем добавляйте подпункты через поля названия и папки. Чтобы изменить пункт, выберите его в списке, отредактируйте поля и нажмите **«Сохранить изменения»**; для удаления используйте **«Удалить пункт»**. В блоке настроек можно изменить родительское название (по умолчанию — **«Файловый обмен»**), включить открытие папки назначения и копирование её пути в буфер обмена после копирования. Кнопка **«Применить изменения»** сохраняет эти настройки; по умолчанию оба чекбокса выключены.

Для обновления распакуйте новый релиз и запустите приложение из него либо выберите его папку кнопкой **«Выбрать сборку…»**. Подпункты и название сохраняются. Панель управления остаётся в распакованной папке и не заменяет свой работающий EXE при обновлении. Настройки относятся к учётной записи, указанной в окне; если UAC запрашивает данные другого администратора, приложение работает с его меню.

При запуске панель в фоне проверяет [GitHub Releases](https://github.com/xromen/FileExchange/releases) и предлагает новую версию. После согласия архив проверяется, приложение обновляется и перезапускается с сохранением настроек. Чекбокс **«Проверка обновления при запуске»** включён по умолчанию и сохраняется сразу при переключении. Ответ **«Нет»** снимает галочку; включить проверку снова можно в приложении. Кнопка **«Проверить обновление»** доступна независимо от этой настройки. Текущая и последняя версии отображаются в окне. При ошибке обновления предусмотрено восстановление предыдущих файлов.

Также доступны прежние команды:

```powershell
.\FileExchange.exe "На сервер" "\\server\share\Обмен"
.\FileExchange.exe "В архив" "D:\Архив"
```

Каждый запуск добавляет один подпункт или обновляет папку существующего пункта с тем же названием. При ошибке доверия сертификату `0x800B0109` выполните `FileExchange.exe --install` от имени администратора. Каждая сборка подписывается новым локальным сертификатом; при обновлении может потребоваться повторная установка сертификата.

[Подробные инструкции по установке, копированию и удалению](FileExchange/README.md).

## Автоматические релизы

После каждого push в `master` [GitHub Actions](.github/workflows/release.yml) собирает панель управления, программу и нативное расширение, проверяет копирование, COM, WPF и диагностику установки, затем публикует ZIP в **GitHub Releases**. При ошибке сборки или проверки релиз не публикуется. Исходники GitHub также предоставляет в релизе автоматически.

Версия вычисляется автоматически как **`1.0.N`**, где N — число коммитов в основной цепочке истории Git (`git rev-list --first-parent --count HEAD`). Каждый новый коммит в `master`, включая merge-коммит, увеличивает N на один. Публиковать и затем переписывать историю `master` нельзя: номер зависит от её сохранности. Старые опубликованные релизы не переименовываются.

Одна версия используется в свойствах EXE и DLL, заголовке WPF-приложения, MSIX (`1.0.N.0`), теге **`v1.0.N`** и имени **`FileExchange-1.0.N-win-x64.zip`**. Например, четвёртый коммит основной цепочки получает `1.0.4`. Повторный запуск для того же коммита использует ту же версию: опубликованный релиз сохраняется, незавершённый черновик дополняется. Если одним push отправить несколько коммитов, архив строится для последнего из них; номера есть у всех коммитов.

Workflow получает полную историю Git. Сборки стоят в очереди; релиз получает отметку Latest, только если его коммит всё ещё находится в вершине `master` на момент публикации. Запуск вручную доступен через **Actions → Сборка и публикация → Run workflow**, для ветки `master`.

Workflow использует встроенный `GITHUB_TOKEN` с разрешением `contents: write`. Добавлять отдельный токен или секреты не требуется. Приватный ключ подписи удаляется после сборки и не попадает в ZIP или Git.

Origin пока не настроен. Создайте пустой репозиторий на GitHub и выполните из этой папки, заменив URL своим:

```powershell
git remote add origin https://github.com/USER/REPOSITORY.git
git push -u origin master
```

Первый push сразу запустит публикацию. GitHub Actions должен быть разрешён в настройках репозитория и организации.

## Локальная сборка

Нужны Windows x64, .NET SDK 10, Windows SDK и C++ Build Tools из Visual Studio для NativeAOT.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\FileExchange\Build.ps1
.\FileExchange\artifacts\app\FileExchange.exe --self-test
dotnet run --project .\FileExchange\ShellExtension\AbiCheck\AbiCheck.csproj -c Release -- .\FileExchange\artifacts\app\FileExchange.ShellExtension.dll
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\FileExchange\Packaging\Test-InstallErrors.ps1
# Проверка WPF без запуска окна и без установки (через DLL, чтобы не запрашивать UAC).
dotnet .\FileExchange\Manager\bin\Release\net10.0-windows\win-x64\FileExchange.Manager.dll --self-test
```

Результат: `FileExchange/artifacts/FileExchange-<версия>-win-x64.zip` и распакованная программа в `FileExchange/artifacts/app`. Метаданные имени архива и версии — в `FileExchange/artifacts/release.json`. Версия относится к текущему HEAD; финальный релизный архив следует собирать после коммита. Для сборки нужна полная Git-копия репозитория. Сборка и проверки не регистрируют меню и не добавляют сертификаты в доверенные.

`Add-FileExchangeMenu.ps1` и `Test-FileExchangeMenu.ps1` — предыдущий вариант для классического контекстного меню; в ZIP программы на C# они не включаются.
