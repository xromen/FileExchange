# Файловый обмен

Программа на C# для Windows 10 и Windows 11 x64. В контекстном меню файлов создаёт общую группу **«Файловый обмен»**. Каждый запуск с названием и папкой добавляет один подпункт. Повторный запуск с тем же названием, без учёта регистра, обновляет его папку.

```powershell
.\FileExchange.exe "На сервер" "\\server\share\Обмен"
.\FileExchange.exe "В архив" "D:\Архив"
```

Используйте `FileExchange.exe` из распакованного релизного ZIP или папки локальной сборки `artifacts\app`. Передавайте два аргумента в кавычках. Относительные пути превращаются в абсолютные относительно текущей папки терминала. Папка назначения может быть локальной или сетевой; она создаётся при первом копировании.

При первом запуске программа копирует свои файлы в `%LOCALAPPDATA%\FileExchangeMenu\bin` и регистрирует расширение для текущего пользователя. Скачанную папку после успешной установки можно переместить. Установленная .NET на целевом компьютере не нужна.

В Windows 11 расширение регистрируется через подписанный sparse MSIX и `IExplorerCommand` для нового контекстного меню. Установщик добавляет публичный сертификат этой локальной сборки в `CurrentUser\TrustedPeople`. Если Windows отклоняет такое доверие с ошибкой `0x800B0109`, нужен один запуск установки от имени администратора: установщик добавит проверенный сертификат в `LocalMachine\TrustedPeople` и повторит регистрацию. Это хранилище доверия распространяется на всех пользователей компьютера. Приватный ключ используется только во время сборки и удаляется. В Windows 10 используется регистрация той же DLL в реестре текущего пользователя. [Механизм меню Windows 11](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer), [системное доверие сертификату MSIX](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing).

При ошибке доверия откройте PowerShell **от имени администратора** в папке сборки и выполните:

```powershell
.\FileExchange.exe --install
```

Добавлять подпункты после успешной установки можно из обычного PowerShell. При любой ошибке регистрации программа выводит оба потока PowerShell и сохраняет журнал `%LOCALAPPDATA%\FileExchangeMenu\bin\Install.log`.

Пакет подписан локальным сертификатом для личного использования и разработки. Каждая сборка получает новый сертификат, поэтому при обновлении может потребоваться повторная установка сертификата. Для распространения через обычный корпоративный установщик потребуется подпись доверенным сертификатом.

## Копирование

1. Выделите один или несколько файлов в Проводнике.
2. Откройте контекстное меню → **Файловый обмен** → нужный подпункт.
3. Файлы копируются отдельным процессом, без блокировки Проводника на время копирования.

DLL получает весь список выделенных файлов через `IShellItemArray`; ограничение в 15 файлов из предыдущего PowerShell-скрипта здесь не применяется. Папки и смешанное выделение файлов с папками не поддерживаются.

Если в папке назначения уже есть файл с таким же именем, программа показывает предупреждение с полным путём и вопросом о перезаписи. **«Да»** заменяет файл, **«Нет»** пропускает его и продолжает копировать остальные. По умолчанию выбрано «Нет»; решение запрашивается отдельно для каждого совпадения. Исходные файлы сохраняются.

После копирования всегда появляется итоговое окно: сколько файлов скопировано (включая подтверждённые перезаписи), сколько пропущено из-за отказа и сколько завершилось ошибкой. При ошибках это же окно содержит их список. Ошибка одного файла не останавливает остальные; копирование файла в самого себя отклоняется.

Если меню после первой установки не появилось, перезапустите Проводник или выйдите из учётной записи и войдите снова. Скрипт уведомляет оболочку об изменении регистрации, но не завершает ваши процессы автоматически.

## Сборка

Нужны .NET SDK 10, Windows SDK с `MakeAppx.exe`/`SignTool.exe` и компоненты C++ Build Tools из Visual Studio для компилятора NativeAOT. Исходники программы и DLL написаны на C#; C++-компилятор нужен только как инструмент сборки нативной DLL.

Из папки `FileExchange`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```

Результат — `artifacts\app`: программа, нативная DLL, sparse MSIX, публичный сертификат, скрипты регистрации и изображения. Готовый архив создаётся в `artifacts\FileExchange-win-x64.zip`. Переносите папку целиком или распакуйте ZIP. Сборка не устанавливает пакет, не меняет реестр и не добавляет сертификаты в доверенные.

## Проверка и удаление

```powershell
# Проверка копирования и конфигурации без установки меню.
.\artifacts\app\FileExchange.exe --self-test

# Только регистрация меню, без добавления подпункта.
.\artifacts\app\FileExchange.exe --install

# Удаление меню и сертификата; для удаления из LocalMachine запустите от администратора.
.\artifacts\app\FileExchange.exe --uninstall
```

Проверка `--self-test` использует временную папку и не меняет пользовательскую конфигурацию. Она проверяет 25 файлов, специальные символы, запрос перезаписи и оба ответа, сохранность исходников, продолжение после отказов и ошибок, итоговые счётчики и текст сообщения, добавление и обновление подпунктов, а также сохранение stdout/stderr и кода сбоя PowerShell в диагностике и журнале. Ответы на перезапись подставляются автоматически; проверка не открывает диалоги.

Проверка реального COM ABI нативной DLL, также без регистрации в системе:

```powershell
dotnet run --project .\ShellExtension\AbiCheck\AbiCheck.csproj -c Release -- .\artifacts\app\FileExchange.ShellExtension.dll
```

После удаления регистрации список папок в `%LOCALAPPDATA%\FileExchangeMenu\destinations.json` и установленные бинарные файлы сохраняются. Настройки имеют вид:

```json
[
  { "Name": "На сервер", "DestinationPath": "\\\\server\\share\\Обмен" },
  { "Name": "В архив", "DestinationPath": "D:\\Архив" }
]
```

Основные файлы: `App/Program.cs` — параметры и установка; `Shared/ExchangeStore.cs` — подпункты; `Shared/FileCopier.cs` — копирование; `ShellExtension/ShellCommand.cs` — обработчик Проводника.

Проверка появления пункта непосредственно в Проводнике требует установки на целевой системе. В текущей рабочей среде установка намеренно не выполнялась.
