# Файловый обмен

Программа на C# для Windows 10 и Windows 11 x64. В контекстном меню файлов и папок создаёт общую группу **«Файловый обмен»**; её название можно изменить через приложение управления. Каждый запуск с названием и папкой добавляет один подпункт. Повторный запуск с тем же названием, без учёта регистра, обновляет его папку.

## Приложение управления

Распакуйте весь архив и запустите **`FileExchange.Manager.exe`**. Windows запросит права администратора. Панель показывает учётную запись, для которой меняются настройки. Если при повышении прав введены данные другого администратора, изменения относятся к его учётной записи.

- **«Установить / обновить»** устанавливает расширение из указанной папки сборки. Для обновления распакуйте новый релиз и запустите панель из него или выберите папку через **«Выбрать сборку…»**. Список подпунктов и название родителя сохраняются. Если DLL занята Проводником, установщик покажет причину и попросит закрыть Проводник перед повторной попыткой.
- В блоке **«Настройки меню, копирования и обновлений»** название содержит «Файловый обмен» при первом запуске и сохранённое значение при последующих. **«Применить изменения»** сохраняет название для Windows 10 и нового меню Windows 11 вместе с состояниями чекбоксов копирования. Пустое название отклоняется. Чекбокс **«Проверка обновления при запуске»** сохраняется сразу при переключении.
- Чекбоксы **«Открывать папку после копирования файлов»** и **«Копировать путь до папки после копирования»** включают открытие папки назначения в Проводнике и копирование её полного пути в буфер обмена. По умолчанию оба выключены. **«Установить / обновить»** также сохраняет их состояния.
- Для нового подпункта заполните название и локальную или сетевую папку, затем нажмите **«Добавить»**. Путь можно ввести вручную, даже если папка пока не существует.
- Для изменения выберите строку, измените название или папку и нажмите **«Сохранить изменения»**. **«Удалить пункт»** удаляет выбранный подпункт после подтверждения. Повторяющиеся названия отклоняются без учёта регистра.
- **«Удалить меню»** снимает регистрацию расширения, сохраняя подпункты и название для последующей установки.
- **«Проверить обновление»** проверяет последний стабильный релиз [xromen/FileExchange](https://github.com/xromen/FileExchange/releases). Под кнопками установки отображаются текущая версия приложения и версия в GitHub Releases.

Панель управления остаётся в распакованной папке. В `%LOCALAPPDATA%\FileExchangeMenu\bin` устанавливаются только файлы расширения и копирования. Копирование из контекстного меню выполняется отдельным процессом с обычными правами пользователя.

## Автоматическое обновление

Чекбокс **«Проверка обновления при запуске»** включён по умолчанию. При его включении последняя версия проверяется в фоне, без блокировки окна. Если доступна новая версия, появляется вопрос об обновлении. **«Нет»** снимает галочку и сохраняет отключение проверки при следующих запусках. Включить её снова можно через этот же чекбокс; его состояние сохраняется сразу. Отключение хранится в файле `%LOCALAPPDATA%\FileExchangeMenu\update-prompts-disabled` и не сбрасывается при изменении настроек меню или копирования. Ранее сохранённый отказ также отображается снятой галочкой. Кнопка **«Проверить обновление»** всегда позволяет вручную проверить и установить новую версию. Если при запуске GitHub недоступен, приложение продолжает работу без сообщения об ошибке; причина доступна в подсказке у строки версии. Ручная проверка показывает ошибку отдельным сообщением.

После согласия ZIP загружается в `%LOCALAPPDATA%\FileExchangeMenu\updates`, проверяется по SHA-256 из GitHub, составу архива и версиям EXE, DLL и MSIX. Встроенный сценарий ждёт закрытия приложения, обновляет файлы в его текущей папке и запускает новую версию. Уже установленное меню также обновляется через существующий установщик; удалённое меню автоматически не устанавливается. Настройки и подпункты сохраняются. Папка приложения должна быть доступна для записи.

Перед заменой создаются резервные копии. При ошибке замены, установки расширения или перезапуска сценарий пытается восстановить предыдущую версию и показывает причину. Проводник автоматически не закрывается: если он удерживает DLL, закройте его окна и повторите обновление. При неудаче журнал `update.log` и резервные копии остаются в уникальной папке внутри `updates`; при успешном обновлении временная папка удаляется.

## Командная строка

```powershell
.\FileExchange.exe "На сервер" "\\server\share\Обмен"
.\FileExchange.exe "В архив" "D:\Архив"
```

Используйте `FileExchange.exe` из распакованного релизного ZIP или папки локальной сборки `artifacts\app`. Передавайте два аргумента в кавычках. Относительные пути превращаются в абсолютные относительно текущей папки терминала. Папка назначения может быть локальной или сетевой; она создаётся при первом копировании.

При первом запуске программа копирует свои файлы в `%LOCALAPPDATA%\FileExchangeMenu\bin` и регистрирует расширение для текущего пользователя. Скачанную папку после успешной установки можно переместить. Установленная .NET на целевом компьютере не нужна.

В Windows 11 расширение регистрируется через подписанный sparse MSIX и `IExplorerCommand` для нового контекстного меню. Установщик добавляет публичный сертификат этой локальной сборки в `CurrentUser\TrustedPeople`. Если Windows отклоняет такое доверие с ошибкой `0x800B0109`, нужен один запуск установки от имени администратора: установщик добавит проверенный сертификат в `LocalMachine\TrustedPeople` и повторит регистрацию. Это хранилище доверия распространяется на всех пользователей компьютера. Приватный ключ используется только во время сборки и удаляется. В Windows 10 используется регистрация той же DLL в реестре текущего пользователя. [Механизм меню Windows 11](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer), [системное доверие сертификату MSIX](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing).

При ошибке доверия откройте PowerShell **от имени администратора** в папке сборки и выполните:

```powershell
.\FileExchange.exe --install
```

Добавлять подпункты после успешной установки можно из обычного PowerShell. При любой ошибке регистрации программа выводит оба потока PowerShell и сохраняет журнал `%LOCALAPPDATA%\FileExchangeMenu\bin\Install.log`.

Пакет подписан локальным сертификатом для личного использования и разработки. Каждая сборка получает новый сертификат, поэтому при обновлении может потребоваться повторная установка сертификата. Для распространения через обычный корпоративный установщик потребуется подпись доверенным сертификатом.

## Копирование

1. Выделите один или несколько файлов и/или папок в Проводнике.
2. Откройте контекстное меню → **Файловый обмен** → нужный подпункт.
3. Объекты копируются отдельным процессом, без блокировки Проводника на время копирования.

DLL получает весь список выделенных объектов через `IShellItemArray`; ограничение в 15 файлов из предыдущего PowerShell-скрипта здесь не применяется. Поддерживаются файлы, папки и смешанное выделение. Для папки создаётся каталог с её именем внутри папки назначения; все вложенные файлы и каталоги, включая пустые и скрытые, копируются с сохранением структуры. Например, `D:\Фото` в `E:\Обмен` копируется как `E:\Обмен\Фото`.

Существующие каталоги объединяются без удаления лишних файлов назначения. При совпадении имени файла, в том числе на любом уровне вложенности, действует вопрос о перезаписи. Символические ссылки и соединения каталогов не обходятся и попадают в список ошибок, чтобы не зациклить копирование и не писать через них в неожиданные папки. Корни дисков/сетевых ресурсов и копирование папки в саму себя или внутрь неё отклоняются; защита проверяет реальные пути, включая соединения в пути назначения.

Если в папке назначения уже есть файл с таким же именем, программа показывает системный диалог с полным путём и вопросом о перезаписи. **«Да»** заменяет текущий файл, **«Нет»** пропускает его; при следующем совпадении вопрос появляется снова. **«Да для всех»** разрешает замену текущего и всех следующих совпадений, **«Нет для всех»** пропускает их. Выбор для всех действует только в текущей операции, включая вложенные папки; файлы без совпадений копируются в обычном порядке. По умолчанию выбрано «Нет»; Escape и закрытие окна пропускают текущий файл. Исходные файлы сохраняются.

Раскрывающийся блок **«Подробнее»** показывает для существующего и нового файлов имя, полный путь, точный размер в байтах, даты изменения и создания в местном времени. По умолчанию блок свёрнут; **«Скрыть подробности»** сворачивает его обратно. Если характеристики файла прочитать не удалось, блок показывает причину.

После копирования всегда появляется итоговое окно: сколько файлов скопировано (включая файлы внутри папок и подтверждённые перезаписи), сколько каталогов создано в копируемой структуре, сколько файлов пропущено из-за отказа и сколько ошибок возникло. При ошибках это же окно содержит их список. Ошибка одного файла или каталога не останавливает остальные; копирование файла в самого себя отклоняется.

Перед показом итога программа выполняет включённые действия после копирования: копирует путь папки назначения в буфер обмена и открывает её в Проводнике. Они выполняются, если скопирован хотя бы один файл или создан каталог, включая пустую папку и частичное копирование с ошибками. Если все файлы пропущены или копирование полностью не удалось, действия не запускаются. Ошибки этих действий показываются в итоговом окне и не мешают выполнению другого включённого действия.

Если меню после первой установки не появилось, перезапустите Проводник или выйдите из учётной записи и войдите снова. Скрипт уведомляет оболочку об изменении регистрации, но не завершает ваши процессы автоматически.

## Сборка

Нужны .NET SDK 10, Windows SDK с `MakeAppx.exe`/`SignTool.exe` и компоненты C++ Build Tools из Visual Studio для компилятора NativeAOT. Исходники программы и DLL написаны на C#; C++-компилятор нужен только как инструмент сборки нативной DLL.

Из папки `FileExchange`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```

Результат — `artifacts\app`: WPF-панель управления, программа копирования, нативная DLL, sparse MSIX, публичный сертификат, скрипты регистрации и изображения. Готовый архив создаётся в `artifacts\FileExchange-<версия>-win-x64.zip`. Переносите папку целиком или распакуйте ZIP. Сборка не устанавливает пакет, не меняет реестр и не добавляет сертификаты в доверенные.

Версия `1.0.N` берётся из числа коммитов основной цепочки Git. Она включается в бинарные файлы, заголовок панели и MSIX; команда `FileExchange.exe --version` выводит её. Новый коммит в master автоматически получает новый patch-номер. Для локальной сборки нужна полная история Git, финальный архив собирается после коммита. ZIP исходников от GitHub без `.git` не содержит историю для вычисления версии; используйте `git clone`.

## Проверка и удаление

```powershell
# Проверка копирования и конфигурации без установки меню.
.\artifacts\app\FileExchange.exe --self-test

# Только регистрация меню, без добавления подпункта.
.\artifacts\app\FileExchange.exe --install

# Удаление меню и сертификата; для удаления из LocalMachine запустите от администратора.
.\artifacts\app\FileExchange.exe --uninstall
```

Проверка `--self-test` использует временную папку и не меняет пользовательскую конфигурацию. Она проверяет 25 файлов, специальные символы, запрос перезаписи и оба ответа, сохранность исходников, продолжение после отказов и ошибок, итоговые счётчики и текст сообщения, добавление и обновление подпунктов, а также сохранение stdout/stderr и кода сбоя PowerShell в диагностике и журнале. Ответы на перезапись подставляются автоматически; проверка не открывает диалоги.

Проверка реального COM ABI нативной DLL, также без регистрации в системе:

```powershell
dotnet run --project .\ShellExtension\AbiCheck\AbiCheck.csproj -c Release -- .\artifacts\app\FileExchange.ShellExtension.dll
```

Проверка WPF-разметки и выбора строки без показа окна, повышения прав или изменения настроек:

```powershell
dotnet .\Manager\bin\Release\net10.0-windows\win-x64\FileExchange.Manager.dll --self-test
.\Packaging\Test-Update.ps1
```

Название родительского меню и настройки действий после копирования хранятся в `%LOCALAPPDATA%\FileExchangeMenu\settings.json`:

```json
{
  "ParentName": "Файловый обмен",
  "OpenFolderAfterCopy": false,
  "CopyFolderPathAfterCopy": false
}
```

Существующие форматы `destinations.json` и `settings.json` совместимы с новой панелью; отсутствующие настройки копирования считаются выключенными. Проверка программы `--self-test` проверяет сохранение названия и чекбоксов, выбор действий после копирования и обработку их ошибок без изменения буфера обмена или запуска Проводника, добавление, переименование и удаление подпунктов, отказ от дубликатов, рекурсивное копирование и слияние папок, пустые и скрытые объекты, вложенные запросы перезаписи, конфликты типов и защиту от рекурсии через соединения каталогов. Соединения создаются и удаляются только в временной папке проверки. Проверка WPF-приложения `--self-test` также проверяет ответы GitHub без сети, сравнение версий, сохранение отказа, SHA-256, состав ZIP и версии бинарных файлов/MSIX. `Test-Update.ps1` проверяет замену файлов и откат на временных данных, без установки меню и изменения доверенных сертификатов.

После удаления регистрации список папок в `%LOCALAPPDATA%\FileExchangeMenu\destinations.json` и установленные бинарные файлы сохраняются. Настройки имеют вид:

```json
[
  { "Name": "На сервер", "DestinationPath": "\\\\server\\share\\Обмен" },
  { "Name": "В архив", "DestinationPath": "D:\\Архив" }
]
```

Основные файлы: `App/Program.cs` — параметры и установка; `Shared/ExchangeStore.cs` — подпункты; `Shared/FileCopier.cs` — копирование; `ShellExtension/ShellCommand.cs` — обработчик Проводника.

Проверка появления пункта непосредственно в Проводнике требует установки на целевой системе. В текущей рабочей среде установка намеренно не выполнялась.
